# 2. Core 3.0.0 — redirect asset issuance fees to development reward address

Date: 2026-08-13

## Status

Accepted (scheduled for Telestai Core **3.0.0**; develop on `feature/core-3.0.0`; validate on **TestNet** before any merge to `main`/`master`)

## Context

Asset issue/reissue/tag operations currently require a fixed TLS amount sent to unspendable vanity burn addresses (Ravencoin-style). Separately, Telestai already pays a consensus-enforced **25% block subsidy** development reward to:

`TesBmcgLQsowvYEYPXpSHkkapoTbVV7Xfe`

Funding development from asset activity while keeping a single treasury destination is preferable to destroying those coins. AuxPoW / merge-mining is **out of scope**. PoW for Telestai is **Meraki** (ProgPoW derivative).

## Decision

As part of **Telestai Core 3.0.0** (Bitcoin Core 30.x–class rebase), change asset-layer fee outputs so required issuance/reissue/tag fees are paid to:

`TesBmcgLQsowvYEYPXpSHkkapoTbVV7Xfe`

instead of the current burn addresses.

Scope:

- Consensus: issue/reissue/tag fee checks require the development reward destination
- Activation height (TestNet first, then mainnet **1,150,000**)
- Wallet, RPC, and Qt/asset UX that construct those outputs
- **Not** included: AuxPoW / merge-mining

Fee **amounts** stay as they are today (fixed TLS). No USDT/oracle pricing in 3.0.0.

## Consequences

- **Hard fork / mandatory node upgrade** at mainnet height **1,150,000** (TestNet: active from genesis).
- Coins already sent to burn addresses remain burned; only post-activation ops change.
- Asset fees become spendable treasury income alongside the 25% block subsidy.
- Issuance costs (500 TLS issue, 100 reissue, etc.) are unchanged; only the **destination** changes.
- Must not merge to main until TestNet confirms fee destination + Meraki + assets.
